# 의류 시뮬레이션 파이프라인

표준 마네킹으로 패턴을 만들고, 격자 체형 12종에 입혀 GLB와 여유량을 산출한다.

## 사전 준비

GarmentCode와 NvidiaWarp-GarmentCode 포크가 필요하다. 라이선스 문제로 각자 설치한다.
격자 바디 GLB 12개는 별도 경로(구글 드라이브)로 받아 obj로 변환해 둔다.

## 실행 순서

| 스크립트 | 하는 일 |
|---|---|
| `make_patterns.py` | 마네킹 3 × 디자인 6 = 패턴 18개 |
| `run_batch.py` | 패턴 18 × 체형 12 = 216개 시뮬 (약 55분) |
| `make_spec.py` | `garment_spec.json` 생성 |
| `make_glb.py` | 히트맵 구워서 GLB 내보내기 |
| `warp_garment.py` | 격자 체형 → 사용자 체형으로 옷 변형 |

## config/

- `standard_{s,m,l}.yaml` — 표준 마네킹. MCM 사이즈표 기준, 가슴 85/94/100, 키 162
- `{design}.yaml` — 의류 6종 디자인 파라미터
- `garment_spec.json` — 18개 옷의 부위별 치수와 기준 여유. 판정에 쓰는 계약 파일
- `ease_target.json` — 핏별 목표 여유 (슬림 +8 / 레귤러 +14 / 오버핏 +30)

## 판정 방식

```
편차 = (옷 치수 − 사용자 치수) − 기준 여유
```

허용 범위는 핏별로 다르다.

| 핏 | 둘레 | 어깨 |
|---|---|---|
| 슬림 | -2 ~ +3 | -1 ~ +1 |
| 레귤러 | -4 ~ +6 | -1 ~ +2 |
| 오버핏 | -6 ~ +12 | -1 ~ +4 |

하나로 두면 편차식이 (마네킹 − 사용자)로 축약돼 세 핏이 항상 같은 사이즈를 추천한다.

## R2 업로드 규칙

```
garments/v1/{design}_{size}__{bucket}.glb
예: garments/v1/shirt_slim_m__H1B2.glb
```

시뮬을 다시 돌려 교체할 때는 같은 키를 덮어쓰지 말고 `v2/`로 올린다.
같은 키에 덮어쓰면 브라우저·CDN 캐시 때문에 프론트에서 옛 파일이 계속 보인다.

## 주의

여유량은 3D가 아니라 평면 패턴에서 잰다. 시뮬이 끝난 옷은 중력으로 몸에 달라붙어
오버핏이든 슬림이든 몸둘레 근처 값이 나온다. 옷을 눕혀놓고 재는 실측 관행과도 이쪽이 맞다.

격자 체형은 키를 3단계, 가슴을 4단계로 양자화하므로 실제 몸과 최대 4.0cm / 3.4cm 어긋난다.
히트맵 임계값보다 큰 오차라 `warp_garment.py`로 사용자 체형에 맞춘 뒤 색을 다시 계산해야 한다.

GLB와 시뮬 결과는 저장소에 넣지 않는다. R2로 서빙한다.
